# 六推进器独立输出链路审查（2026-11-05）

## 本轮确认的工程事实

- CLI 位于 `bluerov2.force_run`，调用 `execute_lbts_plan`，通过 `ThrusterOutput` 共用 direct6 后端；原 `rov_control.py` 仅作 MAVLink 通信、心跳、参数/版本读取和日志，不调用旧 goto/PD/MANUAL_CONTROL 控制。纯 PWM 原先已有，推力测试入口缺失。
- 六路力映射唯一实现为 `bluerov2.t200.T200`。处理后的曲线含 10/12/14/16/18/20 V、201个 PWM 点，单位 N；官方文件原始列为 `Force (Kg f)`，转换常数 9.80665。映射保留正反不对称、1500 μs 零力、死区零段、分支单调处理和电压/推力范围拒绝。曲线是单个官方 T200/Basic ESC R3 的静态系泊初始近似，不是本机推力实测。
- 状态适配器组合 DVL 航位推算的位置/姿态、DVL 速度、飞控 `ATTITUDE` 机体系角速度，不读取 GV7；固定状态顺序为 `[N,E,D,roll,pitch,yaw,u,v,w,p,q,r]`。完整快照原子缓存，缺新合格快照时保留原始时间，按单调时钟增长年龄；明确故障锁存。DVL/飞控数据并非统一硬件采样时钟，年龄不含未测网络/位姿延迟。
- MAVLink 接收循环使用旧工程 `service_io` 的消息数和时长预算，DVL JSON 收包也有字节、行数、行长预算。高频轮询没有读取原点文件或重新计算静态变换；原点摘要每秒低频检查。
- 执行器复用 `DATA64` direct6 私有协议。ArduSub 补丁固定上游 `05fed49b8ee1db3c6bca924e0b334b2e0ece980d`（ArduSub 3.5.4）；`motors_output()` 在六路 HAL 批量写后提前返回，跳过原混控；会话期间 GCS 旧控制输入被隔离，servo relay 不更新；完整六路帧先全部校验再提交。200 ms 命令租约到期转 FAULT 中立，迟到帧不能重新接管。停止状态 HAL 回读不代表 Pixhawk 引脚电气测量。
- 本地保存的只读设备诊断显示当时 ArduSub 3.5.4、`flight_custom_version=05fed49b`、`board_version=0`、未上锁 MANUAL、未发现 direct6 应答，DVL 无有效连接。该快照不是本轮重新连接读取；板卡具体型号未知，不能选真实板卡构建目标。本轮没有连接真机、刷写、解锁或驱动推进器。

## 缺陷与修复

- 原 CLI 缺少六路推力短测，增加 `thrust-test`：输入按模型索引 0..5、单位 N；只加载 T200 与映射，不要求定位、原点或规划文件。离线若提供 `test_voltage_v` 即先做能力核验；连接时以新鲜电压遥测或明确配置电压重新映射。
- 纯 PWM 参数按物理 MAIN1..6；计划/推力按模型索引。三条路径继续共用 `ThrusterOutput` 的能力查询、独占、租约和停止。
- 修复错误的 `code/requirements.txt`（其内容曾是整段用户需求文本），根目录 `requirements.txt` 现在统一转入 `code/requirements.txt`，该文件以 editable extra 安装工程及旧后端需要的 `pymavlink`/测试依赖。
- 将官方原始 XLSX 的工作表和列值与预处理曲线独立比较；不以曲线自反算作为唯一数据验证。
- **模型映射未获物理核验**：配置映射候选为索引0..5→原厂编号1..6→MAIN1..6→曲线符号 `-,-,+,+,-,+`。标准模型位置（x/y/z，m）按索引为 `(+.156,-.111,.085)`、`(+.156,+.111,.085)`、`(-.156,-.111,.085)`、`(-.156,+.111,.085)`、`(0,-.218,0)`、`(0,+.218,0)`；方向分别是 `(-.707,+.707,0)`、`(-.707,-.707,0)`、`(+.707,+.707,0)`、`(+.707,-.707,0)`、`(0,0,+1)`、`(0,0,+1)`。模型头注释称前右、后右等安装位置，但机体 FRD 的 y 数值与部分标签相反；目前没有证据判断是坐标定义还是注释错，不能翻转模型、符号或继续完整轨迹试验。逐路实机确认方向之后应修正标签或映射；若几何数值确需变更，必须重新规划并重验反馈增益。

## 算法遗留差异

未修改规划、机会约束、目标函数、模型参数、反馈增益或控制周期。原对齐日志记录的 Octave 6.4 固定样本比较为 25/26 项通过，机会约束 Python 0.090、MATLAB 源码 0.085。当前环境没有 MATLAB/Octave，本轮完整对齐命令实际退出并报告找不到解释器。独立重建同一 seed 的200个样本后，当前 Python 特征根采样为0.090；按 MATLAB `chol` 分支计算为0.085，二者重构相同协方差，差异来自有限样本采用的旋转根不同，而非概率阈值。原 MATLAB 机会约束核使用 Cholesky，建议经授权后采用 Cholesky 并仅在失败时回退特征分解；这会改变样本及边接受/搜索结果，故本轮不改。

## 本轮测试与限制

- 聚焦执行/状态/T200 测试：117 passed。
- 工程测试：232 passed，排除一个必须创建 UDP socket 的端口占用测试；受限运行环境创建 socket 返回 `Operation not permitted`。旧仓库测试：26 passed。
- 新增纯 PWM 与推力入口模拟后端用例；两类命令各自离线运行均输出 `checked`。推力过能力测试在连接前拒绝。官方原始 XLSX 对应点、方向/零值、非等间隔反馈保持、状态缓存过期和锁存、direct6 原生 C++ 核心测试通过；C++ 输出 `ownership, atomic frame, expiry, replay, disarm, mode, rollover PASS`。
- 本轮尝试完整 Linux SITL 启动；二进制可执行，但沙箱拒绝其绑定 RC UDP 端口5501，因此没有本轮 SITL 结果。仓库既有报告曾记录相同源码/二进制的11项 SITL 检查通过，但属于历史证据，不计作本轮通过。
- 未构建真实 Pixhawk 板卡镜像，未做示波器/逻辑分析仪 PWM 测量、Companion 实机路由、通道方向水测或轨迹跟踪。HAL 回读、历史日志、SITL 都不能替代这些项目。

## 最短实机后续顺序

1. 查清 Pixhawk 板卡/输出引脚和可恢复固件，备份参数及固件；按 `firmware/ardusub_3_5_4/README_zh.md` 在隔离上游源码构建对应板卡目标。不得按 `board_version=0` 猜型号。
2. 部署后先断开推进器/避免产生推力，测量六路引脚中立、帧间更新、正常停止、主机退出和控制断流。再验证 Companion 确实转发 `DATA64`。
3. 通过 PWM 入口逐物理通道确认输出；水中逐路确认编号与正反作用方向，之后记录通道映射并更新核验标志。
4. 核实 DVL/飞控时间、参考、安装旋转和杆臂，确认模型几何/标签；解决 MATLAB 机会约束差异并重新运行原算法核验。
5. 用同一坐标基准重新生成短计划，先离线 `plan` 检查，再短时低速执行；分别报告序列完成、停止确认和轨迹跟踪结果。
